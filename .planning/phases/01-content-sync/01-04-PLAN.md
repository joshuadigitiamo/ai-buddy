<objective>
Read the ClickUp test handbook through the v3 REST API, drop denylisted pages, redact the rest, and produce incremental, citable `HandbookPage` rows that `buddy_core.build_index` stores.

Purpose: SYNC-01 (read the doc from env ids with an env token), SYNC-02 (incremental by date_edited / content hash, never by the update timestamp), SYNC-03 (denylist half), SYNC-05 (URL, title, revision date per page).
Output: `buddy_sync.clickup`, `buddy_sync.handbook`, a synthetic fixture, three test files.

Change-detection refinement (planner decision, recorded here): `content_hash` hashes the stored, redacted title and content, never the raw upstream text. A hash of raw text in a published file would let anyone who has the redacted page guess a masked short secret (a PIN or door code) by hashing candidates. Every fetched page is therefore redacted on each run (cheap) and compared with the previous row; "processed" counts pages whose stored row is new or changed. D-10 still holds: state comes from the previous index.db, keyed on date_edited plus content hash.
</objective>
