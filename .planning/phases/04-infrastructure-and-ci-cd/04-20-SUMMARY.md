# Phase 4 Plan 20: Digest deploys and run-named revisions Summary

**Each CI run now deploys the exact image digest its build step produced under a revision named `<service>-r<run_id>-<attempt>`, so a re-run of the same commit always creates a new revision; the runbook's manual path and the post-publish forced revision follow the same identity scheme.**

## Accomplishments
- Gap 3 (INFRA-05): `_deploy.yml` build step has `id: build`; the render env carries `IMAGE_DIGEST: ${{ steps.build.outputs.digest }}` and `DEPLOY_ID: r${{ github.run_id }}-${{ github.run_attempt }}`; the `:${{ github.sha }}` tag is still pushed. - WR-06: the README "Render and deploy" block uses `git rev-parse HEAD` (full commit), looks up the digest per service with `gcloud artifacts docker images describe ... --format='value(image_summary.digest)'`, exports `DEPLOY_ID="manual-$(date +%s)"`, and notes that a manual replace shifts all traffic at once.
