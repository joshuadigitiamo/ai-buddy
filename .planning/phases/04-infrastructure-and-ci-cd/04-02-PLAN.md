<objective>
Make one MCP server image safe and reachable on every target: an explicit deploy marker that fails closed, an allow-list for pod-to-pod hostnames, and a health route.

Purpose: the v1 audit found the auth guard relies on `K_SERVICE` only (fails open on kind) and plain-http calls to a Service name get 421. Kind (04-07), compose (04-06) and Cloud Run (04-08) all need these seams before their manifests exist.
Output: `deploy_env`, `mcp_allowed_hosts` settings, `/healthz`, two 02-REVIEW hardening fixes (WR-02, WR-05, recommended by the v1 audit before Phase 4), updated env contract and docs.
</objective>

<assumption_delta_decision>
Detector: pluralization (a second deployed host besides Cloud Run: kind). Primary noun now: the deployment environment (`DEPLOY_ENV`: local | production). Decision: promote - `DEPLOY_ENV` becomes the marker every guard reads; `K_SERVICE` is demoted to one signal that forces production. Rationale: a K_SERVICE-only guard fails open on any non-Cloud-Run host (audit warning 4). The same promotion is applied to the bot in 04-03. Invariant test suggested and included: every auth-off knob is refused for every value of DEPLOY_ENV except local, with and without K_SERVICE.
</assumption_delta_decision>
