<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> chat-bot `GET /guarda` | unauthenticated browser requests reach the bot |
| bot page -> storage.cloud.google.com | the browser fetches the private object with the owner's session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-84 | Spoofing / Tampering | `/guarda` open redirect or content injection | high | mitigate | fixed host and the configured bucket only; name and t regex checks; HMAC signature with compare_digest; player page has no script, escaped values and a deny-all CSP except media from Google storage hosts |
| T-04-85 | Information disclosure | bucket name and project id behind the public route | medium | mitigate | unsigned or malformed requests get a bare 404, so scanners learn nothing; only links rendered into the owner's Chat card carry a valid signature |
| T-04-86 | Elevation of privilege | video access widened | high | mitigate | the route never grants access: no signed storage URL, no proxying, no ACL change; GCS still requires the owner's IAM grant and login (D-16) |
| T-04-87 | Information disclosure | route logs | low | mitigate | the handler logs nothing about v, t or s (BOT-11 log hygiene tests stay green) |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | no installs; hmac, hashlib and Starlette are already available |
</threat_model>
